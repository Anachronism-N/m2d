# Wan-Dancer 条件可控性与奖励后训练实验

状态：基线与音乐/种子条件实验已完成工程验收；小预算 SFT 和在线 NFT oracle 对照已完成，独立画质与音乐能力验收仍未通过。补充 gain/tempo/左右指令及匹配 checkpoint 成片继续验收。实测见 [evaluation/EXPERIMENT_PROGRESS.md](evaluation/EXPERIMENT_PROGRESS.md) 与匿名聚合结果；本文件保留正式能力实验的门槛，不将 oracle 工程试验冒充门槛通过。

## 目标与边界

主目标：在不牺牲 RGB 身体正确性、人物身份及自然运动的前提下，验证并改善音乐事件响应和细粒度身体动作指令遵循。先隔离 Global 规划与 Local 细化的贡献，不同时改多 encoder、规划时间采样和 AR。

- 官方与训练上游使用独立净 checkout/环境；旧 diff 与 H3 不修改。
- 数据、原始媒体、权重、逐身份日志、内网地址、凭据均不进入 Git；只发布代码、协议、公开版本与聚合分析。
- 生成失败、pose 拟合失败、低置信样本都保留并计入报告。
- 3 case 是诊断集，不是可靠的 SOTA 排名；正式训练/评估按音乐及人物隔离，去重后冻结 split。
- 不将 NLF/SMPL 拟合成功当作 RGB 无多肢体/液化证据；手指不属于现有可靠自动事件奖励。

## 实验矩阵与推进门槛

### P0：官方正基线

1. 作者官方 KPop 完整音轨、对应参考图及 Global/Local prompt，Global/Local均seed=0，标记为shell参数对齐的受控基线；README KPop Local示例seed=100是另一变体，不宣称逐位复现该演示。工作画布 1280×720，149 逻辑帧，Global 48步，Local 24步，CFG=5，shift=5，单节点8rank USP。
2. 最新上游原生 Local 官方样例单独验证，不把作者包装结果称为上游结果。
3. 完整保存原始输出和配置。工程修复必须单独记录补丁；未经修饰/增强的视频才用于质量验收。

Global 149 逻辑帧通常解码为38张关键帧；作者8fps容器无音乐，其容器时长不是真实编舞时长。Local约149/30秒一窗口；作者包装会裁去padding并trim原音轨末0.2秒，验收区分工作画布、裁剪尺寸、实际帧数和时长。

### P1：固定短片配对诊断

- 恢复交接指定的3个case及原配/换入音乐，共6条；同参考图、同文本、配对种子42。
- 每种音乐重新提取feature并生成Global+Local，不仅替换输出音轨。
- 现有音乐均5.0625秒；这是作者动态fps的短曲条件诊断，不能冒充长曲Global验证。官方长音轨基线另报。
- 同时记录简洁风格prompt与既有详细caption协议，不把BPM/能量文本变化混入音乐操控实验。

### P2：Global/Local条件归因

| 标识 | 操作 | 解释 |
|---|---|---|
| E0 | 同音乐/图/文本换seed | 运动差异底噪 |
| E1 | 换曲重跑Global和Local | 完整系统音乐响应；包含P1 |
| E2 | 固定Global只换Local音乐 | Local是否仍利用音频；锚点可能压制变化 |
| E3 | 固定Local音乐/seed换Global | 规划条件贡献 |
| P-first | Local仅首图mask | 条件依赖诊断，可能分布外，不代表仅首图重训上限 |
| T1 | 左/右、一次/两次、顺序交换等互斥文本 | 每次只改变一个可观测身体事实 |

所有group及偏好对固定相同参考图、音乐片段、prompt、Global、mask、fps与绝对时间offset；不同条件不能混组。

### P3：音乐反事实干预

- 局部增益：保留波形余量防clipping，不逐片响度归一化抵消增益。
- 保持音高的tempo拉伸：候选0.8/1.2，记录warp，并在评价/锚点契约中正确对齐。
- 时间/相位移位：比较正确音轨与错位音轨对应事件。
- 先确认模型实际输入feature改变且时间正确，再分析身体事件/速度/幅度；不要求音量与运动线性对应。

### P4：奖励校准和Best-of-N

先同条件K=4候选诊断；确认资源与评分信号后扩展，具体K与样本数在运行manifest冻结。Best-of-N是奖励验收而非RL。

奖励分维度报告，不预设未经校准的权重：RGB质量/身份、可观测身体动作事件、音乐同步。VideoReward不输入音频，不可代替节拍评分；自建pose BeatAlign明确方向、时间单位、置信度、运动拍定义及空集合行为。官方Wan的0–10视频音频LLM Beat Alignment不得与0–1 pose BAS横比。

对抗负例包括静止、抖动、周期模板、错位音频、遮挡/跟踪失败及身体异常。核查自动排序与独立盲人工排序；同源judge指标不能是唯一成功证据。质量门槛不通过时节拍高分不得补偿畸形。

### P5：后训练对照

已运行的例外仅为低分辨率工程诊断：256×448、149 帧、CFG1、GT 锚点、SFT24步和NFT4次更新。NFT奖励是训练GT latent负MSE，非音乐/画质奖励；未验证歌曲与人物隔离，未满足下述正式能力验收门槛，不据此扩展正式RL。

进入条件：推理/数据/训练保存恢复路径已验证；候选存在可排序差异；reward能在独立样本区分好坏；训练holdout隔离；资源峰值实测。

1. 若基本音乐/动作能力不足：先针对性SFT验证，而非指望RL补齐缺失表示。
2. 对照原始模型、相同参数范围和预算的SFT、奖励加权SFT、一种在线奖励优化方法。小范围Local更新/LoRA先做风险受控诊断，不规定AR s1必须LoRA。
3. 方法候选Flow-GRPO-Fast与DiffusionNFT；先核实Wan-Dancer条件接口与短烟测再选择正式对照，DiffusionART作为新候选单独审计。
4. 冻结Global，正式验收包含真实Global误差；Global RL暂不首轮实施，稀疏规划的音乐reward需下游Local成片及额外rollout成本。
5. 防止静止/抖动/模板化与reward hacking，跟踪参考模型漂移、人工质量、多样性及音频反事实优势。

RL不要求视频AR。若后续硬需求为低首段延迟/在线音频，再单独定义因果条件契约，研究CF++与KVPO，不由本轮默认启动。

## 资源与执行

两个节点均实测8×A80080GB NVLink。第一阶段独立单节点8rank作业；不把Global改为16rank。准备权重/环境/数据期间不启动空跑GPU任务，ready后仅精确替换已审计的资源保留进程，保护其他任务。

先测加载、单次forward、backward、首次optimizer step和保存/恢复峰值，再决定训练并行/offload与预算。官方上游全量示例为8×H200；8×A800资源不是已验证全量/RL配方。

每run_id记录源码/权重revision、数据hash、完整条件、种子、步骤、采样器、时间映射、依赖、GPU/CPU峰值、任务handle、起止及退出码、每产物probe/hash。长命令使用受管理background任务，失败不计完成，重试新attempt并保留原因。

## 已发现的工程风险与处理边界

- 作者两shell默认case不匹配，须使用同一case及真实Global产物路径。
- 作者Local若全rank保存相同中间图/最终concat有并发写风险；rank0修复仅工程变更，需diff记录。
- 作者Local CLI cfg_scale未完全传入；后续CFG变更必须显式接线并验证，默认5正基线不受该值变化影响。
- 模型路径解析与tokenizer目录需显式冻结，避免rank0自动下载未固定版本。
- 作者音频采样率变量逻辑保留为原始基线，不静默修正后声称官方结果。
- 发布目标为用户指定的 Anachronism-N/m2d；初始方案与工具提交已推送并核验远端commit。临时凭据仅用于授权推送，不写日志、remote或持久配置。运行结果与结论在独立结果分支提交；人评和能力验收未完成的限制随结果保留。
